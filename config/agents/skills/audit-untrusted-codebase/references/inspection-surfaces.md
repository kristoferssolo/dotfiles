Use the general sections for every audit. Read ecosystem sections only when their files
are present. These are investigation leads, not automatic findings.

## General capability indicators

Inspect calls and data flow involving:

- Process creation, shell interpolation, `eval`, dynamic imports, native library loading,
  FFI, JIT compilation, and writable executable memory.
- HTTP clients, raw sockets, DNS, tunnels, webhooks, paste services, Tor, IP literals,
  hard-coded domains, and destinations assembled or decoded at runtime.
- Environment variables, home directories, SSH and GPG directories, cloud configuration,
  Kubernetes files, browser profiles, cookies, password stores, crypto wallets, clipboard,
  screen capture, keyboard input, microphones, and cameras.
- Privilege escalation, sudo, setuid, capabilities, namespaces, device access, kernel
  modules, antivirus exclusions, firewall changes, and security-process termination.
- Recursive deletion, disk or boot-sector access, encryption of user files, backup
  deletion, resource exhaustion, fork bombs, and destructive device commands.
- Telemetry that is enabled without consent, collects disproportionate data, or sends to
  an undocumented or mutable destination.

Search both APIs and command strings. Trace wrappers and aliases before reaching a
conclusion.

## Persistence and host modification

Inspect writes to:

- shell profiles, login files, PATH configuration, aliases, and terminal startup files;
- systemd units, cron, `at`, init scripts, udev rules, desktop autostart, and XDG entries;
- macOS LaunchAgents, LaunchDaemons, login items, profiles, and quarantine attributes;
- Windows services, scheduled tasks, startup folders, registry run keys, WMI, and PowerShell
  profiles;
- SSH authorized keys, Git configuration, credential helpers, package-manager config,
  editor config, and browser extensions;
- `/etc`, sudoers, dynamic-loader config, certificate stores, and trusted keyrings.

Determine whether uninstall behavior reverses each persistent change.

## Evasion and obfuscation

Inspect:

- Base64, hex, compressed, encrypted, or fragmented strings that become code, commands,
  destinations, or executables at runtime.
- Long numeric arrays, polyglot files, hidden Unicode, right-to-left markers, homoglyphs,
  mismatched extensions, alternate data streams, and data appended after file trailers.
- VM, container, debugger, CI, hostname, username, locale, or process-list checks that
  gate sensitive behavior.
- Sleep loops, time bombs, geographic checks, dead-code decoys, exception-swallowed
  behavior, self-deletion, history clearing, and log tampering.
- Minified or generated code whose checked-in output cannot be tied to readable source.

Decode only with inert local tools, bounded input sizes, and no evaluation of the result.

## Repository and delivery surfaces

- Inspect `.gitmodules`, `.gitattributes`, LFS pointers, symlinks, executable bits,
  archives, release assets, vendored trees, and nested repositories.
- Inspect `.git/hooks` and repository-local Git configuration as evidence. Never invoke
  configured hooks, filters, credential helpers, signing tools, pagers, or diff drivers.
- Review changes around tags and releases, especially new maintainers, rewritten history,
  dependency bumps, generated files, and binary additions.
- Compare release hashes and signatures only with an authenticated upstream channel.
- Treat documentation that asks users to pipe a download into a shell, disable security
  controls, run as administrator, or expose credentials as an execution path.

## Rust

- Inspect `build.rs`, procedural macro crates, workspace members, `.cargo/config.toml`,
  aliases, runners, rustflags, target linkers, and package metadata.
- Inspect `Cargo.toml` and `Cargo.lock` for Git dependencies, branch or tag references,
  patches, alternate registries, local paths, unexpected features, and native `*-sys`
  crates.
- Trace `std::process::Command`, shell crates, network clients, `libloading`, FFI, `unsafe`,
  environment and home-directory access, and code included with `include!` or generated by
  build scripts.
- Remember that compiling a dependency can execute its build script and procedural macros.
  Do not use Cargo during the static phase.

## JavaScript and TypeScript

- Inspect every `package.json`, lockfile, workspace definition, `.npmrc`, and package
  manager configuration.
- Inspect lifecycle scripts such as `preinstall`, `install`, `postinstall`, `prepare`,
  `prepublish`, and scripts invoked by common development commands.
- Trace `child_process`, dynamic `import`, `require` from computed paths, `eval`,
  `Function`, native addons, WebAssembly, network clients, and credential or browser data
  access.
- Inspect bundled and minified files, package patches, tarball or Git dependencies,
  overrides, and lockfile URLs. Do not run package-manager metadata commands.
- Inspect extensions, Electron preload code, service workers, and editor activation events
  because opening or installing can be the trigger.

## Python

- Inspect `pyproject.toml`, build backends, `setup.py`, `setup.cfg`, requirements and lock
  files, editable or URL dependencies, package indexes, and tool bootstrap scripts.
- Treat the build backend, `setup.py`, plugins, entry points, import hooks, `.pth` files,
  `sitecustomize`, and test configuration as execution surfaces.
- Trace `subprocess`, `os.system`, dynamic import, `exec`, `eval`, deserialization, native
  extensions, `ctypes`, network clients, keyrings, environment access, and home-directory
  traversal.
- Do not import modules or ask Python tooling to inspect the project during static review.

## Go

- Inspect `go.mod`, `go.sum`, `go.work`, `replace` directives, vendored modules,
  `generate` directives, cgo, assembly, and embedded files.
- Trace `os/exec`, shell calls, plugin loading, network clients, credential paths, and
  platform-specific files selected by build tags.
- Inspect `Makefile`, release tooling, and generator scripts separately. Standard Go builds
  do not run arbitrary dependency build scripts, but wrappers and generators can.

## JVM and Gradle

- Inspect Gradle and Maven settings, wrappers and wrapper JARs, plugins, repositories,
  init scripts, buildSrc, included builds, annotation processors, and test agents.
- Trace process execution, scripting engines, reflection, JNI, dynamic class loading,
  deserialization, network clients, and credential stores.
- Verify wrapper JAR provenance without running it. Treat Gradle and Maven configuration as
  executable code.

## .NET

- Inspect project and solution files, `Directory.Build.*`, NuGet configuration, lockfiles,
  MSBuild targets and tasks, source generators, analyzers, native libraries, and scripts.
- Trace `Process`, PowerShell or shell invocation, reflection, assembly loading, P/Invoke,
  registry access, credential stores, and network clients.
- Treat restore, build, source generation, and IDE project loading as possible triggers.

## Native build systems

- Inspect `Makefile`, CMake, Meson, Autotools, Bazel, Buck, custom configure scripts,
  compiler wrappers, linker flags, code generators, and downloaded toolchains.
- Trace process creation, `system`, `popen`, dynamic loading, inline assembly, syscalls,
  privilege changes, raw devices, persistence locations, and network code.
- Inspect prebuilt objects, static and dynamic libraries, firmware, and generated headers.
  Source review does not establish what an opaque object contains.

## Shell and PowerShell

- Read scripts as programs, including expansions, quoting, redirections, traps, aliases,
  functions, heredocs, dot-sourcing, and commands assembled across variables.
- Inspect download-and-execute pipelines, encoded PowerShell, execution-policy changes,
  hidden windows, background jobs, privilege escalation, credential access, persistence,
  history changes, and destructive globs.
- Follow sourced files statically. Never run syntax checks that execute substitutions or
  source the target.

## Nix

- Inspect flakes, lockfiles, overlays, fetchers, derivations, shell hooks, activation
  scripts, Home Manager and NixOS modules, and impurity such as environment or filesystem
  reads.
- Review fixed-output hashes, Git inputs, follows relationships, binary caches, substituter
  keys, and commands run during builds or activation.
- Do not evaluate or instantiate expressions during the static phase. Evaluation can fetch
  inputs or invoke import-from-derivation behavior.

## Containers, CI, and editor automation

- Inspect Dockerfiles, Compose files, entrypoints, devcontainer features, Kubernetes
  manifests, and scripts copied from remote images. Check image pinning, privileges, host
  mounts, devices, capabilities, socket mounts, secrets, and network exposure.
- Inspect all CI workflows, reusable workflows, actions, runner labels, permissions,
  secrets, artifacts, caches, release uploads, and pull-request trust boundaries. Pinning a
  workflow by tag is weaker than pinning an immutable revision.
- Inspect VS Code tasks and settings, extension recommendations, language-server startup,
  debug launchers, JetBrains project files, direnv, mise, asdf, pre-commit, and shell hooks.
- Treat opening the folder, entering the directory, or checking out a branch as potential
  triggers when host tooling has automatic trust enabled.
